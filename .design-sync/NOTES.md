# design-sync notes — copilot-cost-analyzer

## Repo shape

`packages/web` is a **private application** (`"private": true`, builds via `vite build` to `dist/index.html`), not a component library — it has no `main`/`module`/`exports` entry and no barrel `index.ts`. Synced components live in two different subtrees: `Blueprint`/`SegmentedControl`/`Tag` under `src/components/ui/`, and `PromptCompositionIcicle` (added 2026-08-11) under `src/charts/`. Everything else in the app (session list, turns table, panels, other charts) is app-specific composition, not meant to be synced as reusable DS components. The user explicitly scoped this sync (2026-08-11, then extended the same day to add the icicle chart).

There is also an `Industry`-type design-system project already in this claude.ai account (`167fde98-25e2-4c8f-b52b-845e821de90a`) that is **not** related to this repo — it's the generic Claude Design built-in starter kit this app's `theme.css` was originally ported *from* (see `Design/` dir and its `README.md`). Do not sync into it; this repo's target project is `cada26a4-e1c4-4b9f-a3dd-4a7fa5e325ea` ("GitHub Chat Analyser DS"), pinned in `config.json`.

## Build

No library build exists for these components, so the converter runs in **synth-entry mode** — but a plain directory-walk `cfg.srcDir` doesn't work here, because the two component subtrees (`components/ui/`, `charts/`) are siblings with no narrower common ancestor than `src/` itself, and widening the walk to all of `src/` sweeps in `main.tsx` — which mounts the real app to `#root` as a *module-level side effect* and throws in every preview page (breaks ALL components' bundle exports, not just the new one; confirmed by trial). The fix: `cfg.entry` points at a dedicated hand-written barrel, `packages/web/ds-sync-entry.ts` (deliberately **outside** `src/`, so the app's own tsconfig/`vite build` never touches it — see the file's own header comment). It explicitly re-exports exactly the 4 synced components plus 2 helper functions (below). **Adding a 5th component means adding it to this barrel file, not just to `src/`** — nothing gets swept in automatically anymore. `cfg.srcDir: "src"` is still set (harmless — with `cfg.entry` present it's only used for the enrichment pass, and every component is pinned via `componentSrcMap` anyway so even that's inert).

`.d.ts` extraction from synth mode can't resolve unexported local prop-type aliases, so all 4 props contracts are hand-written via `cfg.dtsPropsFor`. Two simplifications to know about: `SegmentedControl`'s real source is generic (`<T extends string>`) — the synced contract uses plain `string` since dtsPropsFor bodies can't carry generics. `PromptCompositionIcicle`'s real `root` prop is a recursive `PromptNode` tree — the synced contract types `children` as `unknown[]` (dtsPropsFor has no prelude slot to declare a named recursive type) rather than trying to express the recursion.

**`PromptCompositionIcicle` is not self-contained** — unlike the 3 UI primitives, it needs its `root`/`malformed`/`colors` props *built* from two parsing helpers, not just passed through. `ds-sync-entry.ts` re-exports `parseSystemPrompt` (from `src/lib/system-prompt-parser.ts`) and `assignIcicleColors` (from `src/lib/system-prompt-menu.ts`) alongside the components specifically so the design agent can call them from the bundle global. The full usage pattern is documented in `.design-sync/docs/PromptCompositionIcicle.md`, wired in via `cfg.docsMap` (this component's `.prompt.md` is NOT synthesized from JSDoc — the source JSDoc on the component stays written for real app developers, in plain ES-import terms, deliberately different phrasing from the docsMap doc's `window.CopilotCostAnalyzerUI.*` framing, which only makes sense to an agent that has the compiled bundle and nothing else).

npm/node in this shell are broken (see `project_npm_shell_function_broken` — bare `npm`/`node` recurse infinitely due to a broken nvm wrapper); use `command npm`/`command node` to bypass the shell function.

## Styling

`cfg.cssEntry` points at `packages/web/src/theme.css` — a global-class stylesheet (not CSS Modules/CSS-in-JS) with a `:root` token layer, ported from a design handoff. Fonts ("Barlow", "Barlow Condensed") load via a Google Fonts `@import` in the stylesheet itself — `[FONT_REMOTE]`, no action needed.

## Re-sync risks

- **New components are never picked up automatically** — `cfg.entry` (the `ds-sync-entry.ts` barrel) is an explicit allowlist by design (see Build above, re: `main.tsx`'s side effect). Adding a component means: add its export to `ds-sync-entry.ts`, add a `componentSrcMap` pin, add a `dtsPropsFor` override if the real prop types aren't exported, author a preview, grade it, re-sync.
- If the user ever adds a real library build (a `main`/`module` entry that exports these components) to `packages/web`, the converter will still prefer `cfg.entry` (it's checked first) — `cfg.entry` would need to be removed too before `dist/` + shipped `.d.ts` take over.
- `theme.css`'s tokens/classes are hand-maintained (not generated) — a rename of e.g. `--color-accent` or `.tag-*` would silently desync `conventions.md`'s vocabulary until the next re-sync's validation pass catches it.
- The two Google-Fonts families are assumed served at runtime by the `@import` — if that ever changes to a self-hosted `@font-face`, `[FONT_MISSING]` will fire on the next validate and `cfg.extraFonts` should be set.
- `PromptCompositionIcicle`'s preview data (`.design-sync/previews/PromptCompositionIcicle.tsx`) embeds real excerpts of `Design/SystemPrompt.txt` inline as string literals (not a file reference — previews compile standalone, no filesystem access at runtime). If that reference file changes or is deleted, the preview is unaffected (it has its own frozen copy) but is no longer drawing from a "current" example — not urgent, just worth knowing if `Design/SystemPrompt.txt` is ever meaningfully updated and someone wants the preview to reflect that.
- The "Default" preview text is `Design/SystemPrompt.txt` lines 1–152 specifically (not an arbitrary prefix) — that file has a `<instructions>` tag opened at line 154 that doesn't close until line 459, so any excerpt cut between 154–458 renders as the malformed/flat fallback instead of a nested tree. Re-verified this by running the app's own tag-balance logic over candidate ranges before picking 152 — don't assume a "looks well-formed" visual skim is enough if re-choosing the excerpt.
